# 共享数据对齐规约(主控侧 × WinPC 侧)

> 2026-10-16 立。目的:**防止双边文件版本打架**(今天已出现过一次:WinPC 跑了旧版 harnessd.py 导致 SyntaxError,而共享上已是新版)。
> 适用范围:SMB 共享 `\\192.168.9.100\DshData`(主控侧挂 /home/myxia/DshData;WinPC 侧 = D:\AgentHome\DshData)。

## 1. 传输规则

| 场景 | 通道 |
|---|---|
| 大文件(>1MB:二进制/包/归档/日志) | **一律走本共享**,不走聊天/频道 |
| 小文件(配置/脚本/文档) | 共享 + 频道知会一声 |
| 结论/决策/状态 | 频道(chat.log) |

## 2. 目录职责(谁写谁读)

| 目录 | 属主 | 内容 |
|---|---|---|
| `_对齐/` | **双边共管** | 本规约+manifest+changelog+校验工具 |
| `AI协调频道/` | 双边共管 | chat.log(append-only)、chat.html(自动渲染) |
| `wb-green/` | **WinPC 运行时** | 绿模全套(ann-agent.exe/harnessd.py/guardian.py/plugs.json/适配器) |
| `harness-mesh-新节点接入包/` | **主控侧发布** | 通用接入资产+指南(新节点从这里拷) |
| `wb-diag/` | WinPC | 诊断日志 |
| `archive/` | 主控侧 | 冷备归档(旧项目/实验件) |
| 根部其它目录 | 老徐既有 | 勿动 |

## 3. 权威源规则(治本)

- **共享副本 = 权威源**;WinPC 的 `C:\wb-green\` 是**部署副本**,必须与共享一致(或显式申报分歧)
- 任何一侧改文件 → ① 改完更新 `manifest.json` 里对应 hash ② 在 `changelog.md` 追加一行 ③ 频道知会对方
- 嫌手动烦:跑 `python _对齐/check_alignment.py --refresh` 自动重算 hash 写回(仍要写 changelog)

## 4. 漂移检查(每次会话开始/大动作前跑)

```
python _对齐/check_alignment.py          # 比对实际 vs manifest,报 drift
python _对齐/check_alignment.py --refresh # 重算并写回(承认现状)
```
输出三类:`OK`(一致)/ `DRIFT(未申报变更)`(文件变了但 manifest 没动)/ `MISSING`(manifest 有文件没了)。
**DRIFT 就是"要搞乱"的早期信号**——看到必须先对齐再干活。

## 5. 命名与版本

- 文件名即契约:不改名只改内容;要改版就改内容+changelog,不搞 v1/v2 文件后缀(今天的 使用说明草稿v1/定稿v2 是特例,已收敛)
- 每个被对齐文件在 manifest 里有:`sha256 前12位 / 字节数 / 最后更新方 / 备注`
